# Project Rules

## Rule 1

VMI is an independent project.

## Rule 2

VMI must remain understandable and maintainable by different AI coding agents.

## Rule 3

All important architectural decisions must be documented.

## Rule 4

Do not replace structured representations with prose.

## Rule 5

Do not claim information is measured when it is inferred.

## Rule 6

Every feature should have provenance and confidence where applicable.

## Rule 7

New features should preserve backward compatibility.

## Rule 8

Training and inference are separate concerns.

## Rule 9

Cloud training is allowed; mobile inference is a primary deployment target.

## Rule 10

Never waste cloud credits on idle compute.

## Rule 11

All cloud resources must have an explicit cost purpose.

## Rule 12

Experimental code must be clearly separated from stable code.

## Rule 13

Every training run must be reproducible.

## Rule 14

Every dataset must have provenance.

## Rule 15

The system should continuously improve feature coverage and efficiency.

## Rule 16

AI coding agents may modify the project only after reading:

- README
- architecture documentation
- schema
- feature matrix
- training documentation
- project rules

## Rule 17

Agents must document important changes.

## Rule 18

Agents must not silently create competing architectures.

## Rule 19

The canonical VMI schema is the source of truth for machine-readable output.

## Rule 20

Observatory telemetry must represent real system events and must never fabricate
training or inference activity.
